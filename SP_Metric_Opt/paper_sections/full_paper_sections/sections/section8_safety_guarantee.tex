\section{Safety Guarantee and Certified Fallback}
\label{section_safety_fallback}

    Although the constrained searching methods in Sections~\ref{section_priority_opt}--\ref{section_config_opt}
    can typically keep important tasks schedulable, Two gaps remain.
    First, the execution-time (ET) prediction the gate is certified against may be inaccurate:
    a gate-passing configuration could still miss deadlines if the environment changes abruptly.
    Second, the search is heuristic and cannot guarantee to find a feasible configuration
    in every environment.

    To close these gaps, this section introduces a \emph{certified safe fallback} (denoted as $(\boldsymbol{P}^{safe},\boldsymbol{Q}^{safe})$),
    a configuration whose schedulability is established offline based on the worst-case scenario analysis.

    \subsection{When the Safety Fallback is Deployed}
    \label{section_fallback_triggers}
    The fallback is deployed whenever:
    \begin{itemize}
        \item The inherited incumbent is no longer schedulable under the updated
        distributions---then the fallback also seeds the search because the optimization framework requires a feasible initial solution to get started
        (Section~\ref{section_initial_solution});
        \item An execution-time change exceeds the drift threshold,
        invalidating the inherited config (Section~\ref{section_initial_solution}). 
        This indicates that execution time prediction may not be accurate in the next interval.
    \end{itemize}

    \subsection{Constructing the Certified Fallback Offline}
    \label{section_fallback_construction}
    The fallback is constructed offline against a worst-case execution-time (WCET) model,
    so its schedulability is guaranteed independently of the online predictions.
    We assume the task set is schedulable under worst-case execution times;
    otherwise no online algorithm can give a schedulability guarantee.
    Under this assumption the fallback is the \emph{DM-Fast} configuration---
    the most schedulable configuration, and the correct seed for both the fallback
    and the online search.

    \begin{definition}[DM-Fast configuration]
    \label{def_dm_fast}
    The \emph{DM-Fast} configuration assigns each QoS-configurable task its shortest QoS budget,
    and orders tasks by Deadline-Monotonic (DM) priorities---shorter relative deadlines first.
    \end{definition}

    \begin{theorem}[DM-Fast schedulability dominance]
    \label{thm:dm_fast_dominance}
    Under preemptive partitioned scheduling with constrained deadlines $D_i \le T_i$,
    if DM-Fast is unschedulable for some safety-critical tasks $\tau_i \in \boldsymbol{\tau}^{safe}$,
    then no configuration $(\boldsymbol{P},\boldsymbol{Q})$ is schedulable for $\tau_i$.
    \end{theorem}
    \begin{proof}
    Since DM is optimal among fixed-priority, preemptive, single-core scheduling~\cite{Leung1982DeadlineMonotonic},
    the system model adopts partitioned scheduling, and such scheduling system is sustainable~\cite{baruah2006sustainable} with worst-case execution time,
    DM-Fast is optimal in schedulability.
    \end{proof}

    By Theorem~\ref{thm:dm_fast_dominance}, given a schedulable task set offline, we can use DM-Fast as the feasible initial solution to initiate the
    proposed optimization framework: first call the constrained beam search algorithm, then iteratively call the incremental optimziation algorithm till convergence
    (\ie calling the incremental optimization algorithm cannot improve the SP metric), then use the final found solution as the certified safe fallback solution.
    This method ensures both schedulability and improves the system-level performance agains the simple DM-Fast heuristic.

    \subsection{Schedulability Guarantee}
    \label{section_schedulability_guarantee}
    In-search gating plus the certified fallback yield the following guarantee
    on the shipped configuration.

    \begin{theorem}[Important-task schedulability]
    \label{obs:safety_fallback}

    Assume the online execution-time prediction upper-bounds the true underlying execution time prediction, 
    then all the safety-critical tasks in $\boldsymbol{\tau}^{safe}$ will meet their given deadline miss tolerance requirements
    under the proposed optimization framework at every scheduler invocation:
    \[
        Pr(r_i > D_i) \leq \Theta_i, \quad \forall \tau_i \in \boldsymbol{\tau}^{safe},
    \]
    \end{theorem}
    \begin{proof}
    Such guarantee is provided by design as the propsoed optimization algorithm always starts with a feasible initial solution (either inherited or the safe fallback),
    and the optimization algorithm only accepts a feasible candidate solution during searching process. Therefore, the final solution is also a feasible solution.
    \end{proof}

    
    \subsection{Extension: how to obtain safe execution time prediction}
    Under the smooth environment assumption, we can estimate the Lipschitz constant of a task's execution time distribution with respect to the environment vector offline, and safely obtain the upper-bound of a task's execution time distribution online throughout one short prediction interval.
    However, the safe execution time distribution obtained by this method may be pessimistic and degrade the system performance. 
    Therefore, we only mention this method for discussion purposes. In our experiments, monitoring abrupt execution time distribution changes is sufficient to ensure the safety-critical tasks are schedulable in all scenarios.
