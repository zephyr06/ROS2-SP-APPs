## 2026-08-28 (Step 4 VERIFIED — root cause found + fixed)

- **User reported failure:** running `python3 scripts/visualize_experiment_results.py all_time_records` (folder path) printed `AnalyzeSP_Metric exited 134 — skipping` with `stderr: Aborted (core dumped)` on EVERY window → empty SP plot. The `.tar.gz` path (run by me earlier the same session) had worked, producing SP values. Same machine, same binary, same script — only the input path differed.
- **Diagnosis gap fixed first:** the reliability guard printed only `stderr` on non-zero exit, but AnalyzeSP_Metric's `CoutError` writes its reason to **stdout** (stderr only carries glibc's `Aborted`). So the real cause was hidden. Added `stdout:` to the guard's failure print (`SP_draw_fig_utils.py`). Re-running immediately revealed: `stdout: /home/.../SP_Metric_Opt/all_time_records/task_characteristics.yaml not exist!`
- **Root cause (NOT the empty-distribution class I'd hypothesized):** AnalyzeSP_Metric (C++) resolves its `--file_path` yaml argument relative to its OWN base directory (`SP_Metric_Opt/`), NOT the shell's CWD. A relative folder input → `cfg = "all_time_records/task_characteristics.yaml"` (relative) → the binary looks under `SP_Metric_Opt/all_time_records/...` → not found → abort every window. The `.tar.gz` path worked only because `tempfile.mkdtemp` returns an ABSOLUTE path, so the binary found the yaml. The data was identical; only absolute-vs-relative differed.
- **Fix (one line, in `visualize_experiment_results.py` `resolve_data_folder`):** return `os.path.abspath(input_path)` / `os.path.abspath(sub)` for folder inputs. Tarball branch already absolute (tempdir). Now both paths feed the binary an absolute yaml path.
