# Sketch — Important-Task Safe Fallback & Offline Convergence Loop (PW.1.3)

> Code-side truth for the important-task safety-performance guarantee (new paper claim) +

> Paths relative to `SP_Metric_Opt/`. Code read 2026-08-02. Compressed 2026-08-02.

## TL;DR
- **Important-task label = top-50% by `sp_weight`**, set at generation time (Python), persisted to YAML → read back by C++ `Task::is_important` (default `false`). One source of truth for every consumer.
- **The framework self-guarantees a safe fallback for important tasks**, NOT a conditional "if ET is upper-bounded" guarantee. Offline pre-compute (`ComputeSafeFallback`) certifies a `{PA,TL}` on the cross-interval worst-case DAG; three runtime triggers (a/b-i/b-ii) keep every shipped interval gate-feasible; the offline BF is gated too. No-safe-solution → **fails loud** (throw→regenerate), never silently ships infeasible.
- **Gate predicate = Option A** (per PW.1.1): every important task must satisfy `Pr(r_i>D_i)≤Θ_i`. Scoped to important tasks only.
- **Convergence loop `OptimizeIncre_w_TL_UntilConvergence` = OFFLINE ONLY** (used by `ComputeSafeFallback`, never the online walk), no cap, stops on no strict `opt_sp_` gain.
- **⚠ Draft drift:** §13.3 ("Can we provide a safety-performance guarantee?") frames the guarantee as *conditional* on a known upper bound; §11's `\sen` note ("how to provide hard safety guarantee") is now *answered/implemented*. Both must be rewritten to state the self-guarantee. (§3.)

## 1. Important-task safety guarantee (the new claim)

**1a. The important-task label.** `Task::is_important` (`RegularTasks.h:111`, `bool`, default `false`) is a **generation-time property**, not computed by the optimizer. Python marks top `IMPORTANT_TASK_RATIO` fraction by `sp_weight`: `n_important=max(1,ceil(N*important_ratio))`; `order=sort(task_ids by (sp_weight,id) desc)`; `task[order[rank]].is_important=(rank<n_important)`. Default `0.5` → **top-50% by `sp_weight`** (`n_important=(N+1)//2`). Persisted to YAML as `important` (`yaml_exporter.py:73`), read back by C++ (`RegularTasks.cpp:87`; written :126). Default `false` for pre-label tasksets. **Why:** every consumer (static-solution priority lock, online during-walk gate, generation-time RTA, miss-rate analysis) reads one persisted label instead of each recomputing a top-X% cut (which could disagree). `sp_weight` = SP contribution weight, so "important" = "tasks whose schedulability matters most to the SP objective." Top-50% (not fixed count) scales with task-set size.

**1b. The offline safe-fallback artifact.** `ComputeSafeFallback(worst_case_dag)` runs **once** before the sim loop, in `RunSimulation` (`SimulationOrchestrator.cpp:321-323`): `worst_case_dag=BuildDAGForObtainSafeFallBAckAcrossIntervals(dag_tasks_vecs_)` then `incr_optimizer_.ComputeSafeFallback(worst_case_dag)`. **Worst-case DAG** (`WorstCaseDAG.cpp:33-80`): fuses every interval's DAG into one. **Non-perf task** dist = point mass at `max(execution_time_max)` across intervals (stochastic dominance). **Perf (TL-flexible) task** dist = point mass at its MINIMUM TL option (least-interference seed). Structural equality across intervals enforced (`TaskStructureMatches`) — only ET dist differs. **The compute** (`ComputeSafeFallback` :1002-1076): runs on a **throwaway sibling** optimizer (`fallback_solver`) so the live incumbent is never seeded from the fallback; forces real ET (not WCET) + TL-opt-on (`GlobalVariables` save/restore); forces `enable_fallback_use_=true` on the sibling so the certificate holds even when the live optimizer is in the measurement arm; seeds at DM PA + TL≤`et_mean` (`SeedTimeLimitsAtOrBelowEtMean`), runs the offline convergence loop `OptimizeIncre_w_TL_UntilConvergence`, then **loud-fail re-gates** the final result via `ImportantTasksMeetThresholds` — a miss means the seed itself was infeasible on the worst-case DAG → not walk-fixable (raising TL worsens interference) → **throw**, do NOT store. On pass, stores `safe_fallback_`. **Why:** the guarantee must hold for **every** interval but the dispatcher sees one at a time; certifying on the cross-interval worst-case DAG (stochastically dominates every interval's ET) means the certified `{PA,TL}` is safe under any interval's actual ET → interval-independent. Computing once offline bounds the online cost: the triggers only *adopt* the precomputed artifact, never re-derive it.

**1c. The three runtime triggers (P0.7) — both online INCR + offline BF gated.** The precomputed `safe_fallback_` is enforced at runtime by **three triggers**, all gated by master flag `enable_fallback_use_` (default `true`=shipped; `false`=the "without fallback" measurement baseline). Entry points: `Optimize_w_TL_ScratchOrIncre` (INCR/INCR_Reopt dispatcher) and `OptimizePureIncremental` (INCR_NO_REOPT dispatcher).
- **(a) ET-jump short-circuit** — `SkipOptOnETJump`→`DetectETJump`: trips on the **first** task whose new/old avg-ET ratio `≥1.5` (`ratio_threshold` default `1.5`; decreased ET never trips). On trip, skip the walk + adopt the safe fallback directly (`AdoptSafeFallbackAsIncumbent`, re-scored under current dag). Runs **before** `AbsorbUpdatedDAG` so `dag_tasks_` is still the saved old dag. *Why:* a sudden ET jump (new environment) can invalidate the warm-started incumbent faster than the walk can repair it; the precomputed worst-case-DAG fallback is certified for exactly such jumps.
- **(b-i) During-walk gate** — inside `UpdateRecords`: on a would-beat (SP-better candidate), commit **only if** every important task's `ddl_miss_chance≤threshold` (`ImportantTasksMeetThresholds`, reading the challenger's final RTA from the cache). Reject → `during_walk_reject_count++` + `return false` (no commit). **Only the incremental path** (`rta_cache_active_`); the reopt from-scratch beam runs disarmed, gated post-hoc by (b-ii). *Why:* "limit the search space to the gate-feasible region" — an SP-better move that makes an important task unschedulable is rejected in place. On a gate-reject the champion is reverted (`OptimizeIncreSingleTask`) so a later eval's diff stays `|diff|≤1`.
- **(b-ii) Post-walk backstop** — `AdoptFallbackIfUnschedulable`: after the walk, re-gate the **final** `res_opt_`. FAIL → adopt the safe fallback (`AdoptSafeFallbackAsIncumbent`), record the worst important-task violator as culprit, then **re-verify** the adopted fallback (certified on the worst-case DAG which dominates every interval → it MUST pass; a second failure = **certificate violation** → throw). PASS → **keep it** — schedulability decides, **not** SP (fallback not adopted even if it would have higher global SP). *Why:* (b-i) only guards the incremental path; the backstop catches the reopt beam's final result + any path (b-i) couldn't reach. Last-resort guarantee the *shipped* `{PA,TL}` is gate-feasible.

**1d. The offline BF is gated too (P0.10).** `AdoptRmFastFallbackIfUnschedulable(dag_tasks,sp_parameters,bf_result)` (`OptimizeFallback.cpp:36-57`) called **inside** `OptimizePA_with_TimeLimitsStatus::Optimize()` (`OptimizeSP_TL_BF.cpp:73`) so **every** BF caller is gated. BF-fails-gate → swap in `RateMonotonicFastGroupLocked` (`OptimizeFallback.cpp:12-16`: RM + important-first group lock + smallest-grid TL via shared `BuildPriorityPlan`). RM-Fast also fails → **throw** ("no safe solution exists — regenerate"). BF has no optimizer instance / live RTA cache → gate is the self-contained overload of `ImportantTasksMeetThresholds` (derives RTAs fresh). **Why:** the guarantee is a property of **the framework's output**, not specific to the incremental optimizer — BF (offline reference solver) must produce a gate-feasible result too, else a BF-optimal-but-infeasible PA would ship. The RM-Fast group-locked plan is the BF analogue of the INCR safe fallback: a cheap, structurally safe floor (important tasks in the top slots → their RTA is self-contained, never interfered by non-important tasks).

**1e. The gate predicate.** `ImportantTasksMeetThresholds` (`SP_Metric.cpp:208-239`): bakes candidate TL into each task's ET dist (`ApplyTimeLimitsToTasksExecutionTime`), applies candidate PA (`UpdateTaskSetPriorities`), then for each **important** task checks `GetDDL_MissProbability(node_rtas[i],deadline) > threshold` → reject. Non-important tasks skipped — guarantee scoped to important tasks. Two overloads: **contract** (`:208`) takes pre-materialized node RTAs (zero-extra-RTA-eval, used by the during-walk gate); **self-contained** (`:245`) derives RTAs fresh (used by `ComputeSafeFallback`'s loud-fail + the BF gate). Enforced constraint = **`Pr(r_i>D_i)≤Θ_i` = Option A** (per PW.1.1 §5): `GetDDL_MissProbability` returns the miss prob (mass strictly above deadline), gate rejects when it exceeds `Θ_i`. **Why:** a "safety-performance guarantee on important tasks" must be a hard constraint on the quantity that matters — the deadline-miss probability of the critical tasks — not a global SP threshold. Scoping to important tasks (not all) makes the guarantee **strong but achievable**: the framework trades non-important tasks' schedulability for SP, while important tasks' `Pr(r_i>D_i)≤Θ_i` is never violated. This is the new claim the paper must state precisely (PW.3) + the guarantee §13.3 must reflect (§3).

## 2. Offline convergence loop

`OptimizeIncre_w_TL_UntilConvergence(dag_tasks_update,beam_search_width)` (`OptimizeSP_TL_Incre.cpp:889-897`): `for (;;): sp_before=opt_sp_; OptimizeIncre_w_TL(dag_tasks_update,beam_search_width); if opt_sp_<=sp_before or ApproxEqualSP(opt_sp_,sp_before,1e-3): break; return opt_pa_`. `OptimizeIncre_w_TL` (the online per-interval walk) is `virtual` so this loop can override it. **No cap.** Termination guaranteed by monotonicity over a finite config space: each adopted move strictly increases `opt_sp_`, finitely many `{PA,TL}` configs → strict improvement cannot continue forever. The `1e-3` tolerance stops once a pass fails to improve beyond RTA noise; the explicit `opt_sp_<=sp_before` guard stops on non-improvement. **Used ONLY by `ComputeSafeFallback`** (`:1039`); online dispatchers call `OptimizeIncre_w_TL` (single pass) or `ReOptimizePeriodic`, **never** the convergence loop. **Why:** a single incremental pass can leave improvement on the table when an ET change cascades through neighbors (adopting task A's new TL shifts the optimal TL for task B, already walked). Looping until no strict gain harvests the cascaded gains — **offline only** (`ComputeSafeFallback` runs once before the sim, outside the per-interval latency budget); the online walk must stay single-pass to bound per-interval cost. The loop is the offline counterpart of the online walk: same primitive, unbounded repeats, used only where the latency budget doesn't apply.

## 3. Draft drift — the guarantee is now SELF-guaranteed, not conditional

**Finding:** the draft frames the safety-performance guarantee as **conditional** on a known ET upper bound, but the code now **self-guarantees** a safe fallback. Two stale spots:
1. **§13.3 "Can we provide a safety-performance guarantee?"** (`section13_real_exp_analysis.tex:72-83`). Current claim: *"…can provide safety-performance guarantee if the execution time distribution in the online environments can be upper-bounded and the estimation is known in advance… Although this assumption is in some conflict with our original proposal about working in an unknown environment…"* — a hypothetical conditional on an assumption that contradicts the paper's own unknown-environment framing. **Code reality:** the framework **self-discovers** a gate-feasible fallback for important tasks (`ComputeSafeFallback` on the worst-case DAG, §1b) and enforces it via three triggers (§1c) + the BF gate (§1d). The guarantee is `Pr(r_i>D_i)≤Θ_i` for every important task, every shipped interval. It does NOT require the online ET to be upper-bounded by the user — the worst-case DAG is built from the per-interval ET dists the framework already collects (PW.1.1 §1). No-safe-solution → **fails loud** (throw→regenerate), never silently ships infeasible. The "in conflict with unknown environment" caveat is obsolete. (§13.3 :81's "a new, and stronger safety-performance guarantee" is now concretely the worst-case-DAG-certified fallback + the gate, not just "higher SP.")
2. **§11 Limitations `\sen` note** (`section11_limitations.tex:1-3`): *"how to provide hard safety / schedulability guarantee / first propose hard schedulability guarantee PA + TL / limit the optimization process's search space into that region."* **Code reality:** this is now **implemented** — the during-walk gate (b-i) IS "limit the search space into the gate-feasible region," and the backstop (b-ii) + BF gate guarantee the final result. The `\sen` note is an answered question, not an open limitation.

**Implication for PW.1.4/PW.3/PW.4:** §13.3 must be **rewritten** to state the self-guarantee (worst-case-DAG certification + three triggers + BF gate + Option-A predicate + loud-fail-on-no-solution), scoped to important tasks. §11's `\sen` note + surrounding "smooth environment assumption" GPR text (PW.1.1's GP removal) must be reconciled: the guarantee is no longer a limitation to flag, it is a contribution to state (likely relocating the guarantee *statement* into methodology §6/§7 per PW.2's re-org, keeping §13.3 as the *discussion*). The "conditional on upper bound" framing must be deleted. Flag for PW.1.4 revision plan + PW.3/PW.4 rewrites.
