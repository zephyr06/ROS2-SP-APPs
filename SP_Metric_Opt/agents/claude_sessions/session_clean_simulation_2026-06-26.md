## Task: Reduce Optimizer/Simulation Export Disk Space

### Problem
- **891MB** of stale `sim_log_*` files exist in `TaskData/` directories (artifacts from `simulation_exp` branch, not generated by current `clean_simulation` branch).
- Current `ExportResults()` in `SimulationOrchestrator.cpp` writes **per-task `response_times_task_*.txt`** files per scheduler per simulation run.
- For thousands of jobs across many intervals, these per-task CSVs accumulate to large sizes.
- User's disk is running out of space during batch simulation experiments.

### Root Cause
- No granularity control for export files. Every simulation run exports full per-job response-time traces unconditionally.
- `GlobalVariables::debugMode` exists but only gates `std::cout` logs, not file exports.

### Proposed Design Fix

#### 1. Granularity Parameter
Add a new parameter (e.g., `EXPORT_GRANULARITY` or `EXPORT_DETAIL_LEVEL`) to `sources/parameters.yaml` with levels:
- `0 (NONE)`: No per-job export files at all; only interval SP metrics
- `1 (MINIMAL)`: Aggregate statistics per interval (sp_metrics only) — default for batch runs
- `2 (TASK_AGGREGATE)`: Per-task summary (miss counts, avg response time) but not per-job
- `3 (FULL)`: Current behavior — per-job `response_times_task_*.txt` files

#### 2. Taskset-Scoped Full Export (Debug Mode)
In Python orchestrator (`run_sim_experiments.py`), add a `--full_export_taskset` CLI arg:
- Defaults to `taskset_0` only (first taskset gets FULL export, all others NONE)
- User can override with e.g. `--full_export_taskset 3` or `--full_export_taskset -1` for all

#### 3. Delete Stale sim_log Files
The `sim_log_*` files in `TaskData/` are stale (from `simulation_exp` branch) and safe to delete.
